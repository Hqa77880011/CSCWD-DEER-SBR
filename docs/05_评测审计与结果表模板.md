## 1. 先冻结三种结果口径

**正式结论使用 `project_fix_v1`：同一数据划分、同一固定 GT、同一 ROI/FOV、全局置信度排序，分别计算真正基于体积 IoU 的 AP3D 和基于平面 IoU 的 APBEV。**

| 结果口径 | 定义 | 能回答什么 | 使用限制 |
|---|---|---|---|
| `paper_reported` | 从明确版本的论文表格引用的作者报告值 | 参考文献在其报告条件下达到的性能 | 保留原表名称、页码和数值；不能冒充本项目跑分 |
| `legacy_reproduction` | 在冻结上游提交及原评价入口下得到的复现诊断值 | 当前上游代码、权重和数据能否接近作者报告 | 仅作复现诊断；当前入口的 BEV 几何结果不得直接重命名 AP3D；不能作为修正后主表的增益参照 |
| `project_fix_v1` | 按本文修正并冻结的项目评价协议 | 同一标准下，基线、新模块及联合模型的真实性能差异 | 所有正式对比、双模块消融与天气结论采用此口径；同时提供 AP3D、APBEV |

这三个名称必须进入配置、原始结果 JSON/CSV 和表格标题，不能仅在聊天说明中区分。不同协议的分数即使都写着 `AP@0.7`，也不得直接相减。

来源与评价协议是两个独立维度：`source_kind` 固定为 `paper_reported / official_checkpoint_reevaluated / retrained`；`legacy_reproduction`、`project_fix_v1` 写入 `protocol`。同一官方 checkpoint 可以按旧入口和修正入口分别复评，其 `source_kind` 都是 `official_checkpoint_reevaluated`。未运行任务可以预先登记计划来源，但只有 `status=completed` 且证据齐全才表示已取得结果。

## 2. 上游代码中的关键发现与处理要求

### 2.1 名称写 3D，不代表几何计算使用 3D IoU

当前上游 `inference.py` 调用 `eval_utils_opv2v.py`；后者把框转换为二维多边形，最终按交并面积计算 IoU。`common_utils.convert_format()` 只取框前四个角点的 xy；没有使用 z 和高度重叠。

固定证据：

- [inference.py：评价模块路由，L61–77](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/inference.py#L61-L77)
- [eval_utils_opv2v.py：框转多边形并匹配，L62–95](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/utils/eval_utils_opv2v.py#L62-L95)
- [common_utils.py：面积 IoU 与 xy 多边形，L147–187](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/utils/common_utils.py#L147-L187)

**处理要求：** 本项目新增并验证体积 IoU 评价路径；BEV 评价另保留。不得把原入口输出换一个列名就作为真正 AP3D。

### 2.2 预测为空时，仍须累计该帧 GT

上游后处理在没有预测候选时返回 `None, None`；数据集的 `post_process()` 仍单独生成 GT。但是 `inference.py` 遇到 `pred_box_tensor is None` 会直接跳过后续计分，因此此类帧的 GT 未进入分母。

固定证据：

- [voxel_postprocessor.py：没有预测返回 None，L345–346](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/post_processor/voxel_postprocessor.py#L345-L346)
- [intermediate_fusion_dataset.py：独立生成 GT，L682–686](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/intermediate_fusion_dataset.py#L682-L686)
- [inference.py：先跳过、后计分，L139–156](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/inference.py#L139-L156)

**处理要求：** 每个规定评测样本都写出预测记录；空预测用长度为 0 的数组表示。GT 总数从冻结标签清单统计，不能由“哪些帧产生了检测框”决定。

### 2.3 必须按整个评测集合的置信度排序

上游 `eval_final_results()` 默认 `global_sort_detections=False`；当前 `inference.py` 没有覆盖该默认值。该 AP 函数采用 VOC 2010 的 precision envelope 积分，也不是 KITTI AP_R40。

固定证据：

- [eval_utils_opv2v.py：全局排序分支及默认设置，L98–178](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/utils/eval_utils_opv2v.py#L98-L178)
- [inference.py：未传全局排序参数，L332](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/inference.py#L332)
- [eval_utils_opv2v.py：VOC 2010 积分，L14–39](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/utils/eval_utils_opv2v.py#L14-L39)

**处理要求：** `project_fix_v1` 固定使用全局 score 降序、VOC 2010 积分。相同 score 用固定的 `sample_id`、`prediction_id` 排序，以保证重跑和打乱读取顺序时结果一致。不得额外将其标为 R40。

### 2.4 不得根据退化后的点数或模型模态改变 GT

当前 `intermediate_fusion_dataset.py` 在 `fov=True` 时，会按当前点云是否落入框筛选 GT：LiDAR+Radar 用两者并集，LiDAR-only、Radar-only 分别依据各自点云。这会使不同天气或模态使用的 GT 集合发生变化。

固定证据：[intermediate_fusion_dataset.py L201–256](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/intermediate_fusion_dataset.py#L201-L256)。

**处理要求：** 先按原始完整标注、固定几何 ROI/FOV 和确定的对象去重规则生成统一 GT 清单，再派生 Normal/Fog/Snow。不能因某个框在雾雪输入中失去点，就从 GT 删除该目标；不能因为只用 LiDAR 或只用 Radar，就更换评价对象。训练标签也采用同一固定原始标签规则。

### 2.5 数据集路由、验证集路径和权重选择必须显式指定

上游 `if 'opv2v' or 'V2XR' in opt.model_dir:` 的第一个字符串恒为真，不能用该分支可靠地区分数据集。项目入口应依据配置中的数据集标识选择 adapter 和 evaluator，不能靠目录名称猜测。

此外：

- 指定 `model_dir` 后，配置取自该目录的 `config.yaml`；不是任意另一份 YAML。[来源：yaml_utils.py L30–31](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/hypes_yaml/yaml_utils.py#L30-L31)
- V2X-R loader 在训练时取 `root_dir`，非训练时取 `validate_dir`。正式 test 必须让评估专用配置的 `validate_dir` 指向官方 test。[来源：basedataset.py L123–126](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/basedataset.py#L123-L126)
- 上游 inference 的 `--eval_epoch` 默认 20，非“最后一轮”；加载函数优先使用显式/默认 epoch，不能假定 `eval_best_epoch` 会自动覆盖它。[来源：inference.py L42–45](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/inference.py#L42-L45)、[train_utils.py L146–164](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/train_utils.py#L146-L164)
- 上游最佳验证权重保存逻辑被注释；训练结束自动调用 inference 时没有传 epoch。不能将其打印的末尾分数直接当作最佳 checkpoint 成绩。[来源：train.py L273–287](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/tools/train.py#L273-L287)

**处理要求：** 在验证集上按预定规则选定 checkpoint，记录 epoch 和 SHA256；所有 Normal/Fog/Snow 正式测试使用同一已选权重，不按测试天气分别挑选模型。验证与测试使用独立输出目录，并记录最终解析的数据路径、样本数、split hash。具体选模指标和运行步骤以 04、06 为准。

## 3. `project_fix_v1` 的统一评价规范

### 3.1 几何与标签规范

| 项目 | V2X-R | Astyx HiRes2019 |
|---|---|---|
| 实验角色 | 多智能体协同主实验 | 真实采集单智能体补充实验 |
| 主评价类别 | 冻结映射后的 Vehicle 类；保存原始类型到 Vehicle 的映射 | Car 类 |
| 评价坐标 | ego LiDAR 坐标，所有 agent 的框先转到该坐标 | `radar_ref`；LiDAR 按标定转换到该参考系；必须先核实轴向和 yaw |
| 固定 xy ROI | 框中心 `0 ≤ x < 140`、`-40 ≤ y < 40` m | 框中心 `0 ≤ x < 99.84`、`-39.68 ≤ y < 39.68` m |
| FOV | 使用 ego 相机标定和已验证的图像宽高做固定几何筛选；以下规定中心投影规则 | 不额外进行相机 FOV 筛选 |
| 点数过滤 | 不按当前点数、天气点数或使用的模态筛 GT | 不按框内点数筛 GT |
| difficulty | 主表不套用 KITTI difficulty | `ALL-admissible`，不分 easy/moderate/hard |
| 主计分 | AP3D、APBEV；IoU 0.3/0.5/0.7 | AP3D、APBEV；可全报 0.3/0.5/0.7，主看 0.5，0.7 为次要严格阈值 |
| AP 积分 | 全局置信度排序 + VOC 2010 积分 | 同左 |

这里的 ROI 和 GT 接纳规则是本项目明确冻结的新协议，不能声称逐项等同于原论文/原 loader。V2X-R 的范围参考上传论文第 6 页 §5.1；Astyx 的数值采用 InterFusion 编码范围作为项目自定评价 ROI，其含义已在此明确。

V2X-R FOV 初版固定为：框中心转换到 ego 相机坐标后，要求深度为正；按相机内参投影得到 `(u,v)`，满足 `0 ≤ u < image_width`、`0 ≤ v < image_height`。预测框与 GT 使用同一规则。不要以“至少存在一个当前输入点投影进图像”代替上述几何规则。若开发阶段采用另一种可见框几何定义，必须在正式实验前统一更改协议版本并重生成清单，不能逐模型调整。

编码范围和评价范围分开记录。例如 V2X-R 当前配置编码 x 约为 `[-140.8,140.8]`，与前向评价 ROI 不同；Astyx z 编码范围 `[-3,1]` 也不构成根据预测结果动态删除 GT 的理由。GT 接纳清单不依赖预测，不随天气、seed、模态或 A/B 开关改变。

先形成 `sample_id → original_gt → admissible_gt` 的静态清单；所有清单保留排除原因、原始对象 ID、坐标转换版本与 hash。对同一 split，Normal/Fog/Snow 的样本 ID、评价 GT ID 和 GT 数应逐项一致。没有目标的合法帧仍保留，因为其中的错误检测需要计 FP。

### 3.2 AP3D 与 APBEV 必须采用不同的 IoU 几何

对本项目常用的直立、仅有 yaw 旋转的 7 参数框，先统一表示为：

`(x_center, y_center, z_center, length, width, height, yaw)`。

若某来源以底面 z 记录框，应先转为中心 z；长度、宽度、角度单位和顺逆时针约定必须统一。输入长度/宽度/高度非正、坐标非有限值的框需要按固定规则报错或记录为无效输出，不能静默变成正确框。

记两个框的 BEV 底面多边形面积为 `A1、A2`，相交面积为 `A_inter`，则：

\[
\operatorname{IoU}_{BEV}=\frac{A_{inter}}{A_1+A_2-A_{inter}}.
\]

各框的高度区间为 `[z1-h1/2,z1+h1/2]` 与 `[z2-h2/2,z2+h2/2]`。高度交集长度：

\[
h_{inter}=\max\bigl(0,\min(z_1+h_1/2,z_2+h_2/2)-\max(z_1-h_1/2,z_2-h_2/2)\bigr).
\]

由此得到：

\[
V_{inter}=A_{inter}h_{inter},\qquad
\operatorname{IoU}_{3D}=\frac{V_{inter}}{l_1w_1h_1+l_2w_2h_2-V_{inter}}.
\]

精确的旋转多边形交集应由经过验收的几何实现计算，不用轴对齐外接框代替。上述体积公式限定于直立 yaw 框；若实际保留任意 roll/pitch 的一般 3D 框，需实现相应多面体体积交集，不能未经说明沿用直立框近似。

### 3.3 匹配和积分规则

对每个数据集、split、天气、seed、类别、IoU 阈值分别计算：

1. 从冻结清单读取该评价集合全部合法 GT，取得固定 `num_gt`。
2. 收集所有合法样本的预测，统一用相同的分数保留阈值、NMS 和固定几何过滤；保存空预测记录。
3. 按整个评价集合的 score 降序排序；同分时用稳定 ID 决定顺序。
4. 每个预测只在同一帧、同一类别的尚未匹配 GT 中寻找最大 IoU。最大 IoU `≥ threshold` 为 TP，否则为 FP。一个 GT 最多匹配一个预测。
5. 计算累计 precision/recall，以 VOC 2010 precision envelope 对 recall 变化点积分。
6. 每个 IoU 阈值重新初始化匹配状态；不能沿用另一阈值的已匹配 GT。

某类别 `num_gt=0` 时，AP 标为 `not_applicable` 并给出原因，不填 0、不混入类别平均。不能把“无 GT 且出现预测”静默当作该类别没有样本：这些预测仍要记录，其是否进入整个集合的 FP 由完整类别集合决定。

### 3.4 AP、mAP、百分比和百分点的写法

- 单个 Vehicle 或 Car 类在固定 IoU 下的指标称 **AP**。一个类别时数值上 AP 与类别平均 mAP 相同，但应优先写清类别。
- 只有明确对多个类别求平均，才写 mAP，并列出类别及缺类处理规则。
- 不将 `IoU=0.3/0.5/0.7` 三个 AP 的平均随意写成 mAP；三个阈值应分列。
- 原始 JSON/CSV 保存 `[0,1]` 的分数；论文表统一显示百分数，例如原始 0.8123 显示 81.23。保存未经四舍五入的原值，不能从截图中反推。
- 增益单位用“百分点（pp）”。在原始分数尺度上，`gain_pp = 100 × (AP_ours - AP_baseline)`；先计算再四舍五入。
- 天气均值若需要，明确写 `mean_adverse_AP3D@0.7 = (Fog_AP3D@0.7 + Snow_AP3D@0.7)/2`，这不是跨类别 mAP。Snow 仅用于最终测试和结果总结，不用于未见天气协议的调参与选模。
- 三个训练 seed 分别完成完整评价，再汇总均值和样本标准差；不要先拼接三个模型的预测再把其当作一个模型的 AP。

### 3.5 后处理初值与完整 GT

按 [06 执行步骤与排期](06_执行步骤与排期.md) 的 `project_fix_v1` 配置，所有正式对照先统一使用：

| 设置 | 冻结初值 | 含义 |
|---|---:|---|
| `score_floor` | 0.001 | 统一保留低分预测，避免各模型采用不同分数门槛而提前截断召回 |
| `nms_bev_iou` | 0.15 | 统一使用旋转 BEV NMS 及相同 IoU 阈值；AP3D/APBEV 使用同一份后处理预测 |
| `max_detections` | 500 | 每个合法样本的预测数上限，固定按 score 和稳定 ID 截取 |
| `gt_truncation` | false | GT 采用完整合法目标列表，不受预测上限或上游 `max_num=100` 填充长度限制 |

这些是本项目设置，不能标为作者原评价配置。正式训练开始前，将它们与过滤顺序、NMS 实现版本一同写入 protocol manifest，并对所有同协议模型冻结；不能为了某个方法的表格表现单独调阈值。训练/评价中的 GT 容器必须能容纳全部合法对象，不能为适配固定长度张量静默丢框。

若验证集检查证明低分截断、NMS 或检测上限不适用，在最终 test 开启前统一修改全部对照，提升协议版本（例如 `project_fix_v2`），保存原因与新 manifest，并按新协议重新评价、必要时重新选择所有受影响的 checkpoint。若 GT 处理本身曾错误截断训练标签，还须重新训练受影响模型。旧、新版本结果分表，不将一次阈值调整算成模块增益。

| 用例 | 固定输入 | 预期答案 | 能发现的问题 |
|---|---|---|---|
| `EVAL-Z-001`：z 错位 | 两框 xy、l、w、yaw 相同，l=w=h=2；z 中心分别为 0 与 3 | 纯几何 IoU_BEV=1，IoU_3D=0 | 只用平面交并比却标 3D |
| `EVAL-EMPTY-002`：空预测仍保留 GT | 两帧各 1 个合法 GT；第一帧只有 1 个完美预测，第二帧预测为空 | GT 总数=2；最大 recall=0.5；VOC 2010 AP=0.5 | `None/empty` 导致漏计 GT、虚增召回 |
| `EVAL-ORDER-003`：帧顺序不影响 AP | A 帧只有一个 FP，score=0.9；B 帧一个完美 TP，score=0.8；全部集合 1 个 GT | 无论输入顺序 A→B 或 B→A，全局排序后 AP 均为 0.5 | 只按帧内排序、依赖数据遍历顺序 |

验收实现还应保证同分预测的稳定排序；同一 GT 的重复预测不能都计 TP。测试日志记录 `test_id、evaluator_commit、expected、actual、passed`。

建议按以下顺序核查，避免不必要的重训：

1. 在几何小用例上验证 BEV/3D IoU 和计分逻辑。
2. 选一个已确定的模型和 checkpoint，只做一次固定推理，保存完整、未按天气改变 GT 的预测文件。
3. 对**同一个 checkpoint、同一份配置、同一批保存的预测和原始 GT**分别运行 `legacy_reproduction` 与 `project_fix_v1`，定位分差来自哪一项评价改动。
4. `project_fix_v1` 的 AP3D/APBEV由同一份预测计算，不需要为两个指标分别训练或重复模型推理。
5. 某些旧导出脚本未保存空帧、原始 GT 或低分候选时，补做一次完整预测导出；不要以此为理由重训全部模型。
6. 正式结果统一使用修正后的 evaluator；论文引用值保留原样，不“修正”成推测的作者成绩。

## 5. 复现实验前必须确认的相关协议

### 5.1 天气抽样理论概率

当前上游 `basedataset.py` 在 agent 循环内使用 `random.randint(0,6)` 且 `aug<=2` 时替换为恶劣天气，因此代码对应的**理论抽样概率**是 `3/7≈42.857%`。这不是已经运行测得的训练占比，也不是“44% 已获论文证实”。上传论文第 7 页 §5.4 只说明 Normal/Fog 随机混合。

[固定来源：basedataset.py L303–339](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/basedataset.py#L303-L339)。

正式运行记录 `p_fog、sampling_unit、weather_seed`，并统计实际抽样次数。若 04 采用另一明确概率，所有基线与消融同步采用；不能同时声称完全沿用上游概率。模拟天气参数、文件后缀与强度映射以 03 的冻结 manifest 为准。

### 5.2 无 RGB 运行不等于删除 FOV 元数据

上游 loader 会读取相机文件，而 FOV 路径使用图像尺寸和标定。项目可移除 RGB 像素加载，改读验证后的宽高与标定，并验证 FOV 掩码一致。这里保留几何约束；不以“图片不训练”为由同时删除内参、外参或改变 FOV。具体适配见 03、06。

[固定来源：basedataset.py L347–348](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/basedataset.py#L347-L348)、[intermediate_fusion_dataset.py L339–368](https://github.com/ylwhxht/V2X-R/blob/f3ebbad95561444a53a17358735b0f0dc4ba89f7/opencood/data_utils/datasets/opv2v/intermediate_fusion_dataset.py#L339-L368)。

### 5.3 Astyx 与 InterFusion 的对比边界

Astyx 的主线为 V2X-R 工程内的单 agent adapter，统一使用 Car、冻结的自定义严格 split、本文 `ALL-admissible` GT 与 ROI、VOC 2010 AP3D/APBEV。0.5 是主要 IoU 阈值，0.7 是更严格的次要指标，0.3 可补充完整曲线。

若追加 InterFusion：

- 主表中的 InterFusion 应标 `InterFusion-adapted`，使用本项目的输入、划分、GT、ROI、训练预算和评价器重新训练/评价。
- 其公开 Astyx loader 存在需要逐项核对的输入处理：点云读取的第四通道选取 `Mag` 而非注释所称速度，以及 `20/96` 的雷达俯仰压缩。主项目固定 radar 输入为 `xyz,V_r`；Mag 可保留作元数据/增强实验，不能无标注混入一部分基线。
- LiDAR 到 `radar_ref` 的刚体标定、轴向、yaw 必须一致；不得将非刚体压缩和标定混为一谈。相关代码证据与字段映射见 03、07。
- 只有在作者 split、输入变换、KITTI evaluator、difficulty 的实际定义均可核实时，才另外报告 InterFusion 原协议复现副表。不能假定原论文 split 已可取得。
- 采用 KITTI AP_R40 时，副表必须写明 `R40`，明确 easy/moderate/hard 如何由有效的 2D 框高度、遮挡、截断等字段形成；字段不支持时不凭空赋予 difficulty。
- 不把 Astyx 的 Car AP 与 V2X-R 的 Vehicle 协同 AP 直接比较，也不把 Astyx 单车结果称为真实车路协同效果。

M2 只检验 softmax simplex 对同时表达两种退化的限制：三类输出中的 `p_miss`、`p_spur` 仍分别与原始双标签计算 BCE，各自采用 AB 已有的独立有效掩码；不归一化目标，也不为此另加一个使用共同掩码训练的 AB。损失权重、数据和监督预算保持一致。

## 7. CSV/JSON 与预测存档字段

### 7.1 主结果采用长表：一行只对应一个计分条件

```csv
run_id,status,dataset,dataset_revision,split,split_manifest_sha256,protocol,protocol_manifest_sha256,source_kind,model_id,ablation_id,training_line,module_a,module_b,seed,training_weather_id,evaluation_weather,evaluation_severity,weather_manifest_sha256,class_name,difficulty,metric_geometry,iou_threshold,ap_definition,ap_raw,num_samples,num_gt,num_predictions,num_empty_prediction_frames,checkpoint_epoch,checkpoint_sha256,config_sha256,predictions_sha256,gt_manifest_sha256,evaluator_commit,roi_id,fov_rule_id,score_floor,nms_bev_iou,max_detections,gt_truncation,global_score_sort,created_at,notes
```

关键字段含义：

| 字段 | 约束 |
|---|---|
| `status` | `pending / running / completed / failed / not_applicable`；未运行分数留空/JSON null，不填 0 |
| `source_kind` | `paper_reported / official_checkpoint_reevaluated / retrained`；记录分数的取得途径；`legacy_reproduction` 是评价协议，不是来源类型 |
| `training_line` | `C / W`；同一主表各行使用同一训练线，不能把 W 权重的 Normal 分数放入 C 表 |
| `ablation_id` | 机制表用 `AB / M1 / M2 / M3 / M4 / M5 / M6 / SUP`；其他任务可留空，必须能回链到唯一配置 |
| `metric_geometry` | `3d_volume / bev_area`，禁止含混的 `3d` 标签掩盖 BEV 实现 |
| `ap_definition` | 主表固定 `voc2010_all_points_global_sort`；R40 副表另设明确名称 |
| `ap_raw` | 完成后保存未格式化的 `[0,1]` 数值；跨类/跨天气均值另行汇总 |
| `num_samples / num_gt` | 来源于固定清单；同 split 不随模型/天气/seed 改变 |
| `difficulty` | 主线固定 `ALL-admissible`；不能临时换成 KITTI Moderate |
| `evaluator_commit` | 实际执行的项目提交号；本次核查的上游提交另存于协议 manifest |
| `config_sha256 / checkpoint_sha256` | 指向实际解析配置与实际加载权重；不能只记录文件名 |
| `predictions_sha256 / gt_manifest_sha256` | 允许第三方不训练模型就复算分数 |
| `score_floor / nms_bev_iou / max_detections / gt_truncation` | `project_fix_v1` 分别为 `0.001 / 0.15 / 500 / false`；阈值和 GT 规则不得逐模型改变 |

### 7.3 每帧预测存档必须保留的信息

每个合法 `sample_id` 至少记录：数据集与 split、scene/sequence、timestamp、ego ID、参与 agent ID、输入天气与强度、框坐标约定、每个预测的稳定 ID、类别、score、7 参数框、原始 GT 引用及固定评价 GT 引用。空预测写 `predictions: []`，文件/记录不能省略。精确的旧入口回放另保留 `legacy_gt_mask` 和其生成条件；该掩码不得进入正式主表的 GT 接纳逻辑。

为支持 evaluator 回放，预测存档应保存同一固定后处理后的全部候选，或同时保留足够低的统一分数阈值下的预测。分数阈值、NMS 类型及阈值写入协议；某个 baseline 不能因默认阈值更高而使用另一套候选截断。

多 seed 汇总另建表，记录 `aggregation=mean_std、n_seeds、seed_list、mean_ap_raw、std_ap_raw`，并引用全部底层 `run_id`。若进行置信区间估计，说明重采样单位；协同连续帧优先按 sequence/scene 分组处理，不能把高度相关的框当作独立实验重复。
