# DEER–SBR 补充实验方案与实施说明

更新日期：2026-10-24。对应论文：*Evidence Routing and Supported Residuals for Cooperative LiDAR–Radar Perception*。

本文规定补充实验的研究目标、数据协议、实验矩阵、执行顺序、预算及实现状态。新增批次使用 schema 5 / `supplement_v1`，与原七组 20 epoch 实验隔离。代码已完成无真实数据功能检查；新增训练、真实数据评测、收敛及资源结果均未产生。可复制命令见 [REPRODUCING.md](REPRODUCING.md)，实际检查记录见 [VALIDATION.md](VALIDATION.md)。

核心验证使用 V2X-R 与真实协同数据 V2X-Radar-C；扩展验证增加 K-Radar 真实天气、Where2comm 第二骨干和针对性机制干预。`F` 表示依据开发证据冻结的唯一 AB 或 N2 结构，目前尚未选定。

## 1. 研究目标与证据要求

| 研究问题 | 所需证据 | 解释边界 |
|---|---|---|
| 区分缺失与伪回波的类型路由是否优于普通门控 | 充分训练的 S0/A/B/AB、SUP、M1/M2；相同可追踪辅助监督；类型响应与检测结果 | 排除容量、训练预算和额外监督造成的差异 |
| 真实 Radar 支撑与幅度边界是否改善修正行为 | M3/M4、NO_NULL、rho/支撑半径单因素；供体、null、支撑内外修正与归一化幅度 | 结构性质与检测收益分别验证 |
| 局部机制能否迁移到真实平台与其他协同骨干 | V2X-Radar-C、K-Radar、Where2comm 底座/+F；同协议强方法比较 | 真实天气、真实协同与跨骨干分别提供证据 |

核心主张 C1 是类型路由、观测支撑与有界修正的组合价值；C2 是该局部机制在已验证平台和条件内的可迁移收益。实验完成前二者均为待检验主张。方法级比较需要同时证明相对公共底座的模块贡献，以及相对充分训练外部方法的精度或成本收益。

由这些数据，补实验必须正面回答四个问题：

1. AB 的 Snow 增益 +3.52 点，在充分训练和不同种子下是否仍然成立？

最终结构由开发集规则确定，AB 与 N2 均为候选。已公开的 Snow 测试成绩不参与下一轮结构选择。

### 2.2 与外部公开结果的关系

原七组属于同一公共骨干内的控制实验。V2X-R 原论文各模型的 batch、轮数和 schedule 存在差异，例如 AttFuse/L4DR 为 30 epoch、CoBEVT 为 40 epoch，见 [原论文 Table 13](https://arxiv.org/html/2411.08402v5#S8.T13)。比较时同时登记样本暴露、有效更新和学习率过程。

原实验使用 `project_fix_v1` 的固定 GT、ROI/FOV、全点插值 AP。没有完成全协议对齐前，外部表中的 AP 与本项目 AP 不直接相减。当前单类别结果称 Vehicle AP；Fog/Snow 均值不称跨类别 mAP。参考结果始终来自 `results/reference/`，不由合成功能检查替换。

## 3. 训练充分性、重复与模型选择

### 3.1 独立训练预算

S0、AB、N2 的 seed 17 为首批先导，随后补 SUP。保持 FP32、有效 batch=8、原输入增强和任务定义。缺少可靠收敛曲线时，60 epoch 是初始候选；配方可依据开发曲线冻结为 30、60 或 90 epoch。

| 独立配方 | MultiStepLR 节点 | V2X-R 有效更新数 | 用途 |
|---|---|---:|---|
| 20 epoch | 10、15 | 20,200 | 历史预算控制；原归档保持不变 |
| 30 epoch | 15、23 | 30,300 | 较短新增预算 |
| 60 epoch | 30、45 | 60,600 | 长预算先导 |
| 90 epoch | 45、68 | 90,900 | 60 epoch 仍持续改善时扩展 |

更新数依据 8,083 个训练样本、完整有效 batch=8、每轮 1,010 次计算，真实数据按实际训练池重算。各配方从头训练；60 epoch 配方中的第 30 轮仅为 `long_recipe_intermediate`，不等同于独立 30 epoch 终点。可按需要增加保留旧 schedule 的 30 epoch 控制，以区分训练时间与降学习率时机的影响。

每次有效更新记录实际 batch、累计 microstep/optimizer step、lr、loss 各项、天气和输入统计；逐轮完整评测 Normal/Fog 开发集并记录最佳轮次。实际更新数、暴露样本数和计划值共同用于比较。

### 3.2 平台判断与停止条件

预先采用以下开发判断：两次降学习率均已发生，最后 10 轮最佳开发均值改善低于 0.3 个百分点，且曲线无持续上升趋势，可标为平台候选。该阈值用于资源安排，仍需检查原始曲线与重复种子。训练 loss 下降而开发 AP 稳定或下降时，不自动延长预算；60 epoch 末仍持续改善时再评估 90 epoch。

充分训练后若 S0/SUP 消除原差异，先检查机制和贡献范围，再决定后续投入，不自动扩大全部矩阵。外部方法保留原生 schedule，并获得相近且预先限定的开发调参机会，例如最多 3 套有依据的配方。

### 3.3 三种子、checkpoint 与 F

关键组使用 17/29/43。seed 联动 Python/NumPy/PyTorch、公共层初始化、采样、天气和训练扰动；方法间使用相同样本顺序及方法无关扰动流。不同外部架构不宣称全部参数初始化相同；Where2comm 底座与 +F 的公共参数保持完全相同初始化。

开发集只用于选模；BN 只保留训练 running 统计或按注册政策在 train 重估；最终测试不拟合 BN。V2X-R 内部组默认固定 32 个 train 样本重估，32/128 等规模敏感性只比较开发成绩。外部方法保留原生归一化；真实数据初始候选使用 running BN。

`latest.rank0.pt` 只用于 online resume；`selected.pt` 用于开发选中权重评测；`budget_epochNNN.pt` 保留配方和中间/终点身份，评测需显式声明预算快照。

F 仅从完整匹配的 S0/AB/N2 × 17/29/43 开发日志及 selected checkpoint 冻结。数据、公共模型参数、损失、预算、选模规则和源码身份必须匹配；每个 seed 按 Normal/Fog AP3D07 均值选模，容差 1e-6 时保留较早轮次。在相对 S0 的三种子平均 Normal 降幅不超过预先登记的 1 个百分点条件下，按三种子开发均值选择 AB 或 N2，完全相同均值时保留 AB。解析冻结文件时复算分数、正常条件约束和唯一赢家。所有 seed、天气及目标平台共用这一结构，不按最终成绩重新选择。

## 4. 比较方法与独立数据协议

### 4.1 外部完整方法与第二骨干

| 方法 | 保留的关键计算/目标 | 比较身份与限制 |
|---|---|---|
| AttFuse | 原生 LiDAR/Radar PFN、AttFuse 与检测头 | 外部基线；不等同于含 phi 投影的内部 S0 |
| AttFuse+MDD | 原生扩散去噪、Radar 条件、正常参考特征与 epoch 相关目标权重 | 额外参考分支、输入监督与成本单列 |
| L4DR | PointNet++ MSG 前景去噪 FAD、前景 focal loss、双向 MME/跨模态偏移、IM2/MSGF | 依作者公开代码补齐；使用共同四通道与固定GT/协同检测适配，方法身份中明确标注 |
| CoBEVT | 原生 SwapFusion、窗口/agent mask、网络深度与通道 | 非整除网格进行 mask 填充并裁切输出 |
| Where2comm / +F | 共同 PFN/骨干/通信掩码/多尺度聚合；+F 在协同前接局部模块 | 相同公共权重初始化、训练池、预算和输入；结构标签必须匹配实际接线 |
| HRCP、REL | 仅在取得足够可核查代码、机制和配方后适配 | 当前未注册可执行训练配置；不以近似结构冒充 |

可执行外部核心矩阵为 AttFuse、MDD、L4DR、CoBEVT，各先一 seed 再补三种子。完整方法保留其原生候选 batch/optimizer/schedule，例如 CoBEVT/Where2comm 的 40 epoch warmup+cosine，K-Radar L4DR 的 35 epoch AdamW/cosine（batch=3、lr=0.001、weight decay=0.01）；受控模块比较则统一公共部分。所有方法登记单帧/多帧、实际输入字段、训练池、额外监督与资源成本。当前已接入路径均为每 agent 单帧；异步替换邻车历史帧，不累积额外观测。

L4DR 依据 [作者代码与K-Radar配置](https://github.com/ylwhxht/L4DR/blob/fcf2d7f0b7c632f9c23f75f720fe691be519d732/K-Radar-main-repo/configs/cfg_PP_L4DR.yml) 实现FAD/MME及额外前景监督。FAD逐真实agent处理可变点数；阈值0.1，GT外扩0.2m忽略带，point focal权重2。CUDA采样/球查询/三邻域使用仓库原有PointNet++扩展，CPU提供参考运算用于功能检查，尚未建立CPU与CUDA逐算子数值等价证据。原生读取、基本输出和原生协议成绩尚待真实数据验证。正式比较使用共同 ego 坐标、固定 GT、类别、ROI、score floor、NMS 与 max detections。原论文数值、原生协议复现与本项目协议结果分别记录。

### 4.2 三个数据集的职责和语义

| 数据集 | 研究职责 | 输入、GT 与 evaluator | 划分身份 |
|---|---|---|---|
| V2X-R | 模拟天气、训练充分性、机制、强基线与第二骨干 | xyz + 上游颜色标量；`project_fix_v1` 固定 Vehicle GT 与 AP | 保留原 train/validate/test；Snow 不参加开发选模 |
| V2X-Radar-C | 真实车路协同迁移；S0/F/MDD-CORR/CoBEVT | 正 ID 车辆 ego 与真实负 ID 路侧；同步 YAML/点云；官方双向 ROI；官方 BEV 与 true-3D extension 分列 | 从官方 train 按 sequence 留出开发；官方 validate 保留最终评测身份 |
| K-Radar | 真实天气下的单车局部融合；S0/F/MDD-CORR/L4DR | OS2-64、官方 sparse Radar、v2.0 labels、header 同步与标定；双类别 revised AP41 | 从官方 train 按 sequence 留出开发；原 official test 帧保持不变并披露固有 sequence 交叠 |

V2X-Radar-C 复现官方 `location+center` 世界框投影与至少一个角落位于 xyz ROI 的规则；ROI 为 [-102.4,-102.4,-8.5,102.4,102.4,3.5]。两侧第四字段按官方 `dopple` 分别归一化，公开 reader 未建立相同物理单位，不能称已校准 Doppler/RCS。真实晴/雨标签与人工 corruption 分表呈现。

K-Radar 按 label header 对齐 Radar/LiDAR 索引，将 LiDAR 与 GT 平移到 Radar 坐标，z offset=0.7；yaw 从 degree 转 rad，half extents 转完整尺寸。输入第四维为官方 sparse 产品的 power，第五维 Doppler 不输入当前四通道模型。GT 使用官方 ROI [0,-15,-2,72,15,7.6] 与 53° 方位角规则，单个真实 agent 显式旁路协同聚合。0.375m pillar 网格用于当前网络 stride 适配，不能写成原生 K-Radar 模型。

K-Radar 最终 test 与 train 的 58 个 sequence 存在官方固有交叠；仅保证 train/development 的 sequence 隔离，不将最终评测称为未见场景测试。不同真实天气的场景组成可能不同，天气 AP 差异不直接等同于纯天气因果效应。

### 4.3 真实数据监督与访问条件

真实数据只有在确认晴天的 train 原帧上，才生成可信删点/注入类型标签。未知自然天气的类型标签保持屏蔽。`MDD-CORR` 限于核验晴天训练池，以原帧作为参考并对输入施加可追踪 corruption；自然雨天原帧不冒充 clean target。其训练池、额外前向与成本必须与原生 MDD 区别登记。严格同池控制可将其他方法的 `data.clean_only` 同设为 true，使用独立 run_id。

数据准备命令只索引本地官方文件，不执行下载。文件入口、目录和可复制准备命令集中在 [REPRODUCING.md](REPRODUCING.md#5-真实数据扩展数据和监督条件具备后)。实际版本的 sequence 数、字段、单位、同步、GT 和类计数以真实文件核验为准。使用条件遵循各数据集正式发布说明；不重新分发修改后的数据。

VoD/VoD-Fog 仅在取得合规访问及完成适配后作为替代或扩展，模拟 Fog 与真实天气分别记录。Astyx 保留为低优先级的小规模适配候选，当前 pending 配置不算完成。缺少真实 Radar 的其他协同数据不使用复制 LiDAR 或生成 Radar 替代本轮多模态主实验。

## 5. 机制、鲁棒性与统计测量

### 5.1 训练消融矩阵

| 变体 | 实际改变 | 目的与执行范围 |
|---|---|---|
| S0/A/B/AB | 无模块/类型路由/受支撑修正/二者组合 | 四格基本消融；关键三种子 |
| SUP | 普通门控/残差，相同可追踪监督与输入增强 | 容量与监督控制，登记实际参数差 |
| N1 | 相同投影大小的非幅度描述 | 继续主张幅度信息贡献时补重复 |
| N2 | 恢复乘法类型幅度先验 | 与 AB 按开发规则竞争唯一 F |
| M1 | 两类合成共享控制 | 核心机制先导，保留稳定主张时三种子 |
| M2 | 排他类型控制 | 共存退化的扩展控制 |
| M3 | 移除硬输出支撑 | 检验支撑限制的独立作用 |
| M4 | 移除 tanh 幅度边界 | 检验有界残差的实际作用 |
| M5 | 去正常恒等正则 | 按结果需要执行 |
| M6 | 切断类型→残差，保留类型→路由 | 分离两条类型控制路径 |
| NO_NULL | 删除空供体选择，保留真实候选 | 检验拒绝不合适供体的必要性；空邻域仍为零供体 |

M1–M6/NO_NULL 是 AB 基础的从头训练控制；F 若为 N2，其解释不自动扩展到 N2。首批 M1/M3/M4 使用 seed 17，仅用于机制筛查；正文保留稳定机制主张时补 29/43。推理时 type/amplitude/donor 的关闭或打乱单独记录为固定权重干预，不改训练变体名，也不代替重训比较。

### 5.2 实际输出诊断与单因素

在独立开发场景产生无新增扰动、只删点、只注入、共存四种输入。V2X-R 类型精度诊断以 Normal 为参考；真实数据只使用已核验晴天开发样本，未知自然天气不生成类型准确率。

连续比例标签报告 MAE 和 soft-label Brier；二分类 AUROC/AUPRC 仅在事先确定正例规则后使用。记录实际模型的路由增益、null mass、供体归一化 RMS/与局部特征余弦、支撑内外修正、`|delta|/s`、raw 残差最大幅度与 tanh 饱和比例。比较按固定场景/GT 分组的误检和漏检时不改变主表 GT。

优先单独检查 rho∈{0.125,0.25,0.5}、支撑半径 r∈{0.4,0.8,1.2}m；不作全参数笛卡尔积。先一 seed 开发筛查，再对结论依赖配置补重复。支撑与幅度边界的结构检查只证明约束，不代替检测收益；不支持的细节缩小贡献表述或简化方法。

### 5.3 针对性鲁棒性

| 条件 | 注册水平 | 约束 |
|---|---|---|
| LiDAR 删点 | 0/0.2/0.4/0.6 | 受控 corruption，不解释为物理天气等级 |
| 伪点注入 | 原点数 0/1%/5%/10% | 记录位置分布、幅度和 source ID |
| 共存 | 删点 0.4 + 注入 0.05 | 检查两类信号同时响应 |
| Radar 保留 | 1/0.75/0.5/0.25/0 | 零支撑样本保留，GT 固定 |
| 模态缺失 | LiDAR/Radar/两者 | 不插入伪点维持 agent |
| 异质退化 | ego/邻车/全体 | 使用同一场景集合 |
| agent 数 | ego-only/2/3/最多5 | 按实际可通信 agent 建立公共集合；不可用数量标 not_applicable |
| 定位 | 平移标准差 0.1/0.3/1m；yaw 0.5/1/2° | 邻车输入只投影一次，ego 与 GT 不变 |
| 异步 | 1/2/5 帧 | 真实历史邻车输入、当前固定 GT；时间频率按数据登记 |

不做所有因素的全交叉。各方法使用相同扰动参数、`perturbation_seed=17029` 和公共样本列表。异步先建立所有水平共有的有效帧交集；agent cap 不通过复制帧满足。K-Radar 不执行协同定位、延迟或异质 agent 试验。

物理 Fog/Snow 多强度需要真实生成或已有对应点云及模拟参数，不能通过改配置声称已具备。原 Snow 结果已公开，可保留为已知 benchmark；新的冻结独立条件承担进一步泛化验证。

### 5.4 统计与效率

每种子独立选模并报告各天气 AP、mean±sample std（ddof=1）及逐 seed 配对差。V2X-R 的 Fog/Snow 均值先在每 seed 内计算，再统计标准差；天气间必须使用同一 checkpoint。汇总核对共同固定 GT、样本、扰动、结构与 checkpoint 角色，预算快照和选中权重分组；不同预算的 baseline 不自动择优配对。

sequence bootstrap 成对抽取 sequence，每次汇总该抽样内的预测/GT 并重新计算 AP，不平均逐帧 AP；它描述测试场景不确定性，不替代训练种子方差。关键差异不稳定时仅增加关键方法重复，不把所有附录控制扩为五种子。

效率在相同 GPU/精度/batch/agent 分布下记录参数、allocated 峰值显存、局部模块与端到端 p50/p95。端到端串行包含点文件 IO、预处理、传输、forward、解码和 NMS，排除 AP 与落盘；局部另一次计时包含 phi/DEER/SBR，排除 PFN/Scatter/协同。CUDA 前后同步，下一帧前释放上一帧及局部探针张量。MDD 训练参考分支与推理去噪成本分别报告。当前未实现真实通信包字节审计，不据此提出低通信结论。


### 8.1 实现中冻结的关键语义

- **新旧隔离。** 新批次 schema 5 / `supplement_v1`，独立 `outputs/supplement`。原七组配置、参考结果及权重未改。原始科学源码保存在 `repro/archive/legacy_v4_runtime.zip`；原 `scripts/reproduce.py` / `scripts/pretrained.py` 命令从该包执行，并核对原源码身份。源码包中的科学源码及七份配置保持原字节；发布 helper 已同步修复 Windows 关闭文件后再替换、无符号链接权限的数据视图，以及 POSIX receipt 路径。原权重身份验证保持不变，真实 CUDA 复现仍需已验证环境。
- **预算与选模。** 20/30/60/90 独立配方分别使用 [10,15]/[15,23]/[30,45]/[45,68]；原 20 轮配方不变。完整方法保留各自原生候选配方，例如CoBEVT 40轮warmup+cosine、K-Radar L4DR 35轮AdamW/cosine。内部受控比较有效 batch 8；完整外部方法登记其原生 batch（AttFuse为8，K-Radar L4DR为3，其余已接原生候选为2），记录实际更新/样本暴露，真实数据不套用 1010 步。原生/独立配方的 run_id 分离，原生配方后缀为 `_native`。online 仅用于 resume；selected 与明确标注的 budget snapshot 才能进入新评测。真实数据初始候选保留 running BN，不直接套用 32 样本规模；`bn-sensitivity` 固定内部权重，在 train 重估 32/128 等样本后仅比较开发成绩。所有验证和 BN 拟合来源都与最终测试隔离。
- **机制身份。** M1 共享类型，M2 排他类型，M3 去硬输出支撑，M4 去 tanh 幅度边界，M5 去正常恒等正则，M6 只切断类型→残差而保留类型→路由。NO_NULL 删除空供体选择，空邻域仍产生零供体/零受支撑修正。推理干预写在 `evaluation.intervention`，不改 trained variant 名称。
- **外部方法。** 保留 native AttFuse、MGF、SwapFusion、Where2comm 通信掩码和多尺度聚合、MDD 三步扩散及参考特征目标。共同固定 GT / ignore-band 正确的检测 loss 属于项目协议适配，不能声称逐项复制原论文成绩。CoBEVT 在当前非整除 BEV 高度上使用 mask 填充和输出裁切；MDD 修复单 agent 的 batch 维度丢失。L4DR已补FAD/MME与GT前景focal目标，MSGF由融合分支产生门控；其公共检测头、四通道、可变点数及固定GT属于显式适配。各方法均为单帧输入，异步只替换邻车输入帧，不累积额外帧。
- **初始化与扰动。** 17/29/43 联动 Python/NumPy/PyTorch、公共层初始化、数据顺序、天气与训练扰动。完整外部模型保留原生构造顺序；公共 PFN 按 seed 初始化，不宣称不同架构所有层都相同。Where2comm 底座与 +F 的公共参数完全共用相同初始化规则。推理 corruption 使用独立固定 `perturbation_seed=17029`，与方法 RNG 无关。
- **真实 GT 与字段。** V2X-Radar-C 使用正 ID 车辆 ego 和真实负 ID 路侧，同帧 YAML 配对；世界框用官方 `location+center` 语义，ROI 为官方 [-102.4,102.4] 两向协同范围，使用至少一个框角落在 xyz ROI 的规则。第四维严格复现官方 `dopple` 的两侧归一化；公开 reader 未证明该字段在两侧有相同的物理单位，不能写成已校准 Doppler/RCS。K-Radar 用 header 对齐 Radar/LiDAR 索引、v2.0 标签的 degree / half-extent 转换、calibration x/y 与 z_offset=0.7；LiDAR 和 GT 转到 Radar 坐标，稀疏 Radar 第四维是已生成产品的 power，Doppler 第五维不输入当前四通道模型。模型明确旁路单车协同聚合，绝不复制 agent。
- **评分与划分的核查结果。** V2X-R 保留原 evaluator。V2X-Radar-C 官方公开 OpenCOOD 累加器使用 BEV polygon IoU，故官方 BEV 与 `true3d_extension` 分别命名；开发主指标是统一新增的 true-3D AP07，不冒充原论文官方 3D 成绩。K-Radar 调用 pinned 官方 revised AP41（`z_center=0.5`），只替换精确 CPU IoU 后端及小样本计算分块。其官方 train/test 各覆盖全部 58 个 sequence；开发集从官方 train 整 sequence 留出，官方最终 test 帧保持原身份，因此只保证 train/development 的 sequence 隔离，不能声称官方 test 是场景独立盲测。具体源文件见 [官方评分源说明](../opencood/project/official/README.md)。
- **真实 MDD 身份。** `MDD-CORR` 只在核验晴天的 train 子集训练，其他自然天气没有 clean target。它的训练池、额外参考分支及成本都在配置/输出中登记；需要严格相同训练池时，可将其余真实数据配置的 `data.clean_only` 同样设为 true，并使用新的 run_id。真实数据主表不得把此适配写成原生配对天气 MDD。
- **计时边界。** 端到端入口串行包含点文件读取、预处理、传输、forward、解码、NMS，排除 AP 和落盘；局部模块另一次计时，包含 phi/DEER/SBR，排除 PFN/Scatter/协同。CUDA 前后同步。当前只检查实现，没有资源实测结果。没有实现真实通信包字节审计，因此不输出低通信结论。

**调度的受控差异（C）。** CoBEVT/Where2comm保留项目既有 `cosine_warmup`：按epoch更新，前10轮线性warmup，之后以 `(epoch-warmup)/(epochs-warmup)` 到min_lr。作者V2X-R的 `train_utils.py` 构造timm scheduler使用 `epochs*n_iter_per_epoch`，其 `train.py` 又调用 `scheduler.step(epoch)`；接口/时间单位不一致，不能凭YAML宣称运行轨迹相同。本次保留既有项目协议并明确登记，不以提速为由更换调度。K-Radar L4DR的更新粒度则有作者明确调用链，已按A类修复；其一轮T_max使LR跨轮下降/回升，不擅自改成35轮单次衰减。

**共同评测适配（B）。** 全方法单帧、共同ego坐标、一次点投影；V2X-R用xyz+encoded red scalar，不能解释为校准Doppler/RCS。训练天气/删点注入/来源追踪、固定GT、ignore-band正确的检测loss、每轮完整开发验证、score=.001、NMS=.15、最多500预测与现有选模规则保持共同协议。原生score=.2、依天气点数过滤GT及不同验证频率未移植。三个数据集的类别、ROI/FOV、AP定义和划分仍分别按§4.2/§8.1；不同原生协议AP不相减。L4DR detach/插值及K-Radar optimizer/scheduler修复属于训练实现更正，须用本轮源码重新生成配置，不能续接此前schema5实验并声称相同配方。
