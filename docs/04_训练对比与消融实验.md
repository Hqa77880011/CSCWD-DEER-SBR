> 工程更新（2026-10-19）：训练入口、选模、完整恢复和 78 项 pending 矩阵已建立；本次没有执行正式矩阵。RTX 4090 推荐统一 FP32、microbatch 4、累积 2、8 workers，AMP 尚未通过完整稳定性检查。当前训练方法为 `teacher_free_v4`，不再需要教师或冻结 RMS 工件；旧协议单独归档。 详见 [08_实现验收与训练资源配置](08_实现验收与训练资源配置.md)。

> 版本：2026-10-19。本文是后续训练计划，所有本项目正式结果当前均为“未运行”。短训BN失配已按v4共同统计策略完成训练分区核查，完整eval数值与恢复检查通过，证据及限制见08；本轮不启动正式实验。采用 [02](02_两个创新模块设计.md) 的两个候选模块、[03](03_数据准备与天气协议.md) 的数据/天气协议、[05](05_评测审计与结果表模板.md) 的 `project_fix_v1` 评分规范。目标不是预填正向结果，而是用同一预算检验两个模块是否各自有效。

## 1. 先规定成功是什么意思

### 1.1 四个核心版本

本项目底座记为 **S0**：双模态编码 + 共享基础融合/输出投影 + 原始 Radar 旁路 + 固定检测头。在 V2X-R 中保留同一 AttFuse 协同外层，在 Astyx 中使用单智能体路径。S0 是为模块消融冻结的底座，不等同于官方未经修改的 AttFuse 或 L4DR。

| 运行名 | A 证据路由 | B 有界修复 | 用途 |
|---|---:|---:|---|
| S0 | 关 | 关 | 公平模块基线 |
| S0+A | 开 | 关 | 验证 A 独立贡献 |
| S0+B | 关 | 开 | 验证 B 独立贡献；不能暗中调用 A |
| S0+A+B | 开 | 开 | 验证联合贡献 |

四组的基础投影、原始 Radar 旁路、主干、检测头、标签处理和评测器都相同。新增旁路或修复官方评测错误产生的收益，不计作 A/B 收益。

四格检验“模块及其规定训练目标”的整体收益。A 增加可信类型辅助任务，B 使用检测损失、弱幅度约束和正常恒等约束，不再有教师特征修复监督。所有方法共享同一来源 ID 扰动。SUP 进一步匹配类型辅助任务、容量和预算；一个 SUP 不能独立隔离 A/B 每个细节的贡献。

### 1.2 预先指定主指标和目标

本项目主要采用基于体积 IoU 的 AP3D。APBEV 单列为辅助/与上游实现对照的指标。V2X-R 按所用标注中的统一 Vehicle 检测类评价；单类结果准确写作 `AP3D`，不因原表使用 mAP 就省略类别定义。

| 目标 | 预注册的比较方式 | 成功方向 |
|---|---|---|
| 核心天气增益 | V2X-R，W 线，test，IoU=0.7；`M_weather=(AP3D_Fog+AP3D_Snow)/2`；比较 AB 与同线 S0 | 希望提高约 2–3 **个百分点**；这是目标区间，不是已经取得的成绩，也不因超过3点判为失败 |
| 客户指定的天气强对照 | W 线 AB 分别对同协议 L4DR、L4DR+MDD、AttFuse+MDD | 三天气完整报告；希望 Fog、Snow 各自提升，不能只用平均值掩盖某一天气下降 |
| 晴天主表 | V2X-R，C 线，Normal test，IoU=0.7；同时列 validation 三阈值 | 希望 AB 超过 C 线 S0 与 L4DR；不要求超过所有文献方法 |
| 天气模型的晴天行为 | V2X-R，W 线，Normal test，IoU=0.7 | 希望同时优于相关 W 线强对照；对 S0 若下降超过 0.5 点则触发分析。0.5 是本方案的诊断阈值，不是客户新增验收条款 |
| 第二数据集 | Astyx，Car AP3D，主看 IoU=0.5，另报0.3/0.7；C/W分别比较四组 | 检查同方向有效性与不确定性；不强求与 V2X-R 相同幅度 |

“百分点”计算：在 0–100 尺度上直接相减；若原始 AP 是 0–1，先乘 100。以上目标只与**同数据、同训练线、同评分器、同 GT 清单**的本项目重训/兼容权重复评值比较。原论文值留在引用表中，不拿来计算本项目模块提升。

客户提到“晴天和极端天气都超过 L4DR/L4DR+MDD”。本方案把它落实为 **C 线晴天对照 L4DR；W 线在 Normal/Fog/Snow 上对照 L4DR 与 L4DR+MDD**。若还要检验“仅晴天训练的 MDD”，可追加 C-MDD，不能将混合天气训练的 MDD 权重放进 C 线而不标记。

## 2. 两条训练线与 checkpoint 选择

| 项目 | C：Clean | W：Weather |
|---|---|---|
| 模型训练输入 | Normal | 4/7 Normal、3/7 Fog，每 agent 稳定采样；Normal 时隙以0.5概率来源 ID 删点/注入 |
| 常规几何增强 | 按冻结底座配置 | 与 C 同类；正常/天气配对使用一致变换 |
| 类型监督 | 经核实的正常负标签 | 可信缺失/伪回波标签，有效掩码内计算 |
| SBR 学习 | 检测 + 幅度/正常恒等约束 | 同左；不使用教师或正常特征模仿 |
| 类型正例来源 | 无正例，仅正常负例 | provenance_v1 来源 ID 正例；Fog 未核验部分屏蔽 |
| Snow | 不进入训练和调参 | 不进入训练和调参 |
| 模型选择 | 最大 Normal validation 主 AP3D | 最大 `(Normal validation主AP3D + Fog validation主AP3D)/2` |
| 同分处理 | 分数差≤1e-6时选更早epoch | 同左 |
| 最终评测 | Normal validation、Normal test | 同一已选权重评测 Normal/Fog/Snow test |

V2X-R 模型选择主阈值0.7；Astyx 为0.5。W 线选择分数对 Normal 与 Fog 等权，防止只根据雾 AP 选出严重损害正常表现的模型。选择后记录 `selected_epoch`、验证得分、配置 SHA256、权重 SHA256。

**一条 W 线的同一模型不为三种测试天气分别选择三个最佳 checkpoint。** 模块版本、阈值、窗口和损失超参数只在 Normal/Fog validation 上确定，测试 Snow 不是试错集。C/W 不共享已接触天气数据的最终初始化；可共享同源通用预训练，并对全部方法一致登记。

正式候选种子为 **17、29、43**。在同一 seed 内，配对使用相同数据顺序、天气调度、几何增强调度。控制随机流不随模型多调用一个随机函数而改变天气。多卡用相同有效 batch 及优化器更新次数，不能只记录“训练30轮”。

## 3. 训练预算、容量和额外监督如何匹配

### 3.1 首版可执行预算

| 设置 | V2X-R 主线初值 | Astyx 主线初值 | 性质 |
|---|---:|---:|---|
| Epoch | 30 | 160 | V2X-R基础配置为30；Astyx160借鉴InterFusion配置，但统一底座训练方案是本项目决定 |
| 目标有效 batch | 8 个协同样本 | 8 个单车样本 | 本方案默认；显存不足用累积，不只调小某个模型 |
| 优化器 | Adam | Adam | 为统一底座的项目选择；不声称完全复现InterFusion的Adam-onecycle |
| 初始 LR | 0.002 | 0.001 | 项目起点；只在训练/验证上进行少量统一预算调参 |
| weight decay | 1e-4 | 1e-4 | 项目起点 |
| LR阶段 | epoch10、15，乘0.1 | epoch80、120，乘0.1 | 后者是项目自定 |
| 模块通道 | 64 | 64 | 与02的共享接口一致 |
| 精度设置 | FP32基准，AMP通过一致性检查后可统一启用 | 同左 | 不给某一行不同精度却比较延迟 |

L4DR/MDD等外部强对照必须保留其原方法目标；适配前的教师数量与额外训练成本记未知，不能提前写零或擅自删掉其恢复监督。共同输入/预算控制与方法原生目标分别登记。

这些是清晰的初始实验配置，不是已经调好的最佳设置。训练启动前必须检查坐标范围、anchor、正负样本分配是否适合数据；不能机械沿用不同框中心约定的 anchor。

`B_effective = B_micro_per_gpu × world_size × accumulation_steps`。若不能恰好达到8，先冻结一组所有方法都能运行的有效 batch，并记录修订；不能为了公平名义把4张卡视为96GB共享显存。梯度累积不等价于 BatchNorm 的大 batch；四组使用一致的归一化策略，记录 BN 冻结/同步设置及其对预训练权重的影响。

评测器修正和去 RGB 不应改变训练预算。修正 GT 筛选若也影响训练目标，必须对同一新比较组的全部模型一致处理，并清楚标记 `project_fix_v1`，不要声称这组训练逐项等同旧论文。

### 3.2 来源、辅助任务和资源必须匹配

v4 不依赖 S0-C 教师，不读取教师 checkpoint，也不校准冻结 RMS。当前学生真实占据特征产生 detached 单帧尺度，细节见02。正常点数组配对仍可用于可信类型目标构造，不会经过第二个网络；删除教师没有删除 DEER 必要的类型监督。

W 默认 `provenance_v1`：概率0.5、删点比例0.2、注入比例0.05、偏移上限0.3m，仅在 train 的 Normal 时隙执行。S0/A/B/AB/SUP/M1–M6 共用相同 sample/agent/epoch/seed 的扰动流，GT 不变。Fog 的真实缺失/伪回波语义尚未核验，因此未知区域全部屏蔽。来源 ID 扰动不是物理雾/雪真值，不与旧无增强协议混表。正式 W 有 A 版本须通过两类正例和源码/数据/参数绑定审计。

SUP 使用普通门控、普通残差，同量级参数、同一观测增强和可信类型标签、同一辅助权重及更新预算。类型输出不连入 gate/residual。SUP 使用共同动态尺度与损失覆盖规则，但不采用本方法的硬输出支撑、局部候选控制或 tanh 边界。报告实际参数和显存，不称严格等容量。

AB 超过 S0 但未超过 SUP 时，须降低机制主张。旧教师版若另行恢复实验，必须使用历史源码、独立初始化/checkpoint/输出目录和结果表；不能把其成绩直接计为 v4 的 S0 或 AB。v4 当前入口拒绝旧 version=1 配置及旧恢复工件。

| L4DR 协同扩展+MDD | V2X-R，W | 关键对照必须有实际记录 | 若当前主工程无可直接运行配置，需要适配；缺失时明确目标未验证 |
| AttFuse+MDD | V2X-R，W | 必须自跑或兼容权重复评 | 检查与当前双模态底座接近的强恢复基线 |

三种记录来源固定为：`paper_reported`、`official_checkpoint_reevaluated`、`retrained`。另有 `pending` / `failed`，不能用作者值填进重训值列。官方权重如果不匹配类别、训练天气、帧累积、输入字段或版本，就不能作为直接公平对照。

客户允许多数背景方法引用，因此优先把有限算力用于 S0 四组及 L4DR/MDD 关键对照，文献表保留完整视野。不能只有“Ours 与论文数字”，没有同协议自跑对比。

## 5. 数清需要训练多少次

### 5.1 P0：先完成单种子的完整闭环

使用 seed17，所有模型保持已冻结的预算。首次短跑仅用于工程验证，不进正式结果表。

| 任务组 | 计算 | 独立训练数 |
|---|---|---:|
| 两数据集四组主体，C/W | 2数据集×2训练线×4版本×1seed | 16 |
| V2X-R强对照 | L4DR-C、L4DR-W、L4DR+MDD-W、AttFuse+MDD-W | 4 |
| 模态诊断 | 2数据集×2单模态×W×1seed | 4 |
| SUP控制 | 2数据集×W×1seed | 2 |
| **P0合计** | 不含短跑、不含可复用的兼容权重、不含额外超参候选 | **26** |

其中16个核心模型最终产生：8个C模型×2个报告split=16项，8个W模型×3个天气=24项，合计 **40项最终核心评测**。每epoch的模型选择验证另外计时。天气切换是复用同一个checkpoint评估，不是每种天气重新训练一次。

### 5.2 P1：推荐正式证据版

在 P0 基础上为核心四组、关键强对照和 SUP 增加 seed29、43：

| 任务组 | 独立训练数 |
|---|---:|
| 两数据集×两训练线×四核心版本×三种子 | 48 |
| V2X-R四个强对照任务×三种子 | 12 |
| 两数据集SUP-W×三种子 | 6 |
| 四个单模态任务保留单种子诊断 | 4 |
| **P1累计** | **70** |

P1核心最终评测为 **120项**：C线24个模型×2个split=48；W线24个模型×3天气=72。对已选模型的验证成绩随运行归档，不重复误计为独立训练。

三种子是本方案建议的正式证据强度，不是客户额外指定的硬件承诺。若截止前只能完成 P0，则标明单种子、完成了哪些表、哪些强结论仍缺证据，不把 P0 自动包装成稳定的三种子结果。完整工期用 [06](06_执行步骤与排期.md) 的实测吞吐计算。

## 6. 机制消融：四格之后还需要回答为什么

先完成以下 **V2X-R W线 seed17 的8项增量训练**，其他设置与 AB 一致。因此 **P0主体26次 + 机制8次 = 34次**，**P1主体70次 + 机制8次 = 78次**。26/70不包含这里的8项；40/120也只计算核心模型的最终评测，不包括强对照、SUP、单模态及机制评测。若关键结论依赖某项，后续才对该项补三种子或Astyx重复。

| ID | 与AB相比的唯一机制变化 | 核心问题 |
|---|---|---|
| M1 | 同一隐藏层后只预测一个共享受损分数，分别替代两个类型输出；原始双标签和两项BCE保留 | 区分缺失与伪回波是否必要？ |
| M2 | 两个独立sigmoid改为正常/缺失/伪回波三类softmax，保留原始双标签、独立有效掩码和同一BCE损失 | 允许两种退化同时存在是否有价值？ |
| M3 | 仅取消 B 最终输出中的 `S_R` 乘法，候选筛选、空候选与其他输入不变 | 没有硬输出支持约束时，无观测区域修复是否增加误检？ |
| M4 | 去掉 B 的tanh边界，保持同一残差网络 | 有界修复是否比普通残差稳定？ |
| M5 | 去掉正常样本恒等损失 | 晴天保护是否来自这一项？ |
| M6 | B的两幅类型输入为0、`has_A=0`，但A仍控制模态融合且B仍接收Z_A；主v4已没有额外幅度先验 | A/B联合效果是否来自类型条件输入？ |
| N1 | DEER幅度描述换成 occupied mean/RMS，投影层/参数量/初始化/广播方式与AB相同 | 幅度信息是否比同样新增的活跃容量更有用？ |
| N2 | 仅恢复B的v2类型幅度乘子，其余保持v4 | 去掉重复类型幅度限制是否改善检测学习？ |

M1令 `d_shared=sigmoid(h_shared(E))`，将其同时代入原来的 `d_miss/d_spur`，其余显式路由和B类型输入不变。类型损失仍为两项独立掩码BCE，分别对同一个分数施加原始缺失/伪回波监督；因此单头被迫对不同类型给出折中值，不将其命名为已校准的“至少一种退化概率”。隐藏层、步数、监督覆盖和权重保持一致，报告减少的末层参数，不通过增加无用参数声称严格等容量。

M3保留候选占据筛选，仅删除最终 `S_R` 输出约束，构成单变量消融。即使没有 Radar 候选、donor 为0，修复网络仍接收 `Z`、类型和其他观测输入，可能产生非零残差，因此该消融有效。若还想取消候选级占据筛选，应另列增强实验，不能把两个不同约束的删除混为一次单变量比较。

M2令 `(p_normal,p_miss,p_spur)=softmax(logits)`，把后两者作为原来的两个输出；仍对 `p_miss`、`p_spur` 分别使用原始标签、原始独立有效掩码计算二元交叉熵，不改为需要标签互斥的单一类别交叉熵，也不强行归一化训练标签。其输出受 `p_miss+p_spur≤1` 约束，难以同时表达高缺失、高伪回波，这正是被检验的表示限制。为避免初始化差别影响路由，按实际初始类型分数补偿路由偏置，使两模态权重仍为0.5；记录多出的正常类输出参数。该项无需另加一组掩码不同的AB训练，不把相近复杂度误说成相同表达能力。

SUP已提供“普通门控/残差且同等类型辅助任务”的控制，不能用一个未接触共同来源扰动/标签的普通卷积对照代替。更多内部开关，如无空候选、无Radar旁路、单独去掉每一个头、无可信掩码，按02列为增强项，不要求一开始全量展开。

四格结果按同一seed计算：

\[
\Delta_A=M_A-M_0,\quad \Delta_B=M_B-M_0,\quad
\Delta_{AB}=M_{AB}-M_0,\quad
I=M_{AB}-M_A-M_B+M_0.
\]

报告全部三天气，不能只展示正向单元格。交互项 I 可以为负；若 AB 未超过最佳单模块，不能称“两模块互补已证实”。

## 7. 不需要重训即可完成的重点验证

使用固定已选 W 线权重，以相同扰动manifest评价 S0、A、B、AB及关键强对照。

| 测试 | 设置 | 要验证的主张 |
|---|---|---|
| 标准天气 | Normal、Fog、Snow | 主任务完整表现 |
| 分强度 | 03规定的额外雾/雪强度 | 是否只记住一种退化 |
| 不均匀协同天气 | 只ego受损、只一个协作方受损、全体受损 | 本地观测管理是否改善整体协同，而非仅单车更强 |
| 有效智能体数 | 在固定完整GT上测试1/2/3/全体agent；确定性选择邻近agent | 收益是否来自协同；不能每减少agent就删掉其负责的GT |
| Radar破坏 | 点丢失20%/40%、速度噪声0.5/1m/s | 不把Radar“天气较稳健”误认为永远可靠 |
| 标定压力 | 供体额外平移0.2/0.5m，yaw偏移0.5°/1° | 小型局部支持会不会被错位误导；属于压力测试，不代表真实位姿噪声分布 |
| 自然稀疏 | 按正常观测点数、距离分组统计 | A是否把远距离/空旷区域一律判坏 |

第一轮选最能解释机制的2–3项增强测试即可。所有参数在最终测试前冻结。Snow 主结果出来后只能做描述性分析；若据此改方法，原测试已变成开发集，必须重新建立独立测试证据。

## 8. 跑分以外应保存哪些机制证据

### 8.1 模块A

- 两个标签的有效监督覆盖率、正负样本比例和按距离分层的分布。
- 在可信标签区域计算BCE/Brier与AUPRC；类别高度不均衡时不只报Accuracy。
- 缺失与伪回波同时出现的网格占比；双头各自的Recall/误报率。
- 自然稀疏正常区域的错误抑制比例，与纯密度阈值/普通门控比较。

### 8.2 模块B

- 支持覆盖率、空候选选择率、修正幅度均值/高分位、触及边界的比例。
- 没有支持时修正必须为0；有支持不等于真实目标，记录Radar破坏后的误检变化。
- +B是否有独立AP增益；若输出长期为0，其独立贡献未成立。
- 正常天气误检数/固定精度下召回，以及去恒等约束后的变化。

### 8.3 可视化

至少保存6组具有固定sample_id的点云/BEV案例：正常、雾、雪各含成功和失败例；同一案例并排比较S0、AB、GT，以及缺失/伪回波图和修正幅度图。只用点云与BEV，不为视觉好看重新引入客户不使用的RGB模型输入。

示例选择规则在看最终结果前确定：例如每种条件按固定sample_id抽样，再补预注册“最严重错误类型”的案例。标出选例规则，不只展示本方法成功、基线失败的画面。

## 9. 统计和效率报告

**三种子成绩：** 给出每seed AP、均值与样本标准差；改进量按同seed配对后求平均。3个seed不足以支持很强的分布假设，不默认把小均值差写成显著提升。

**置信区间：** 有资源时对同一已选checkpoint做按场景/group的配对bootstrap（计划1,000次），每次重新汇总全局AP，并同时抽取对应Normal/Fog/Snow。不能把单帧AP平均当总体AP，也不能把该区间当作训练随机性的全部不确定性。Astyx若分组依据有限，说明相应局限。

**推理延迟：** 同设备、同输入batch=1、同agent数、同精度、同后处理；预热50次，之后测200个预先固定的真实样本，显式GPU同步。数据加载/CPU预处理和模型+后处理分开记录，另给端到端值。不要拿论文18ms直接作本项目速度基线。

**资源：** 参数量、峰值显存、训练GPU小时、来源标签构造成本、同一稠密BEV格式的通信字节。v4 教师网络/教师前向/正常特征缓存成本为0；来源标签CPU预处理仍计入加载等待。首版A/B不额外跨车发送支持图；实际序列化字节应验证，不能只凭结构图宣称“通信零增加”。

最终表格与结果字段见 [05](05_评测审计与结果表模板.md)。正常完成、训练失败、数据缺失、评测失败分别保留状态。任何一个基线或模块表现不佳，都不能通过删除该行使比较看起来完整。

## 10. 第一次开跑的顺序

1. 通过03数据审计和05评分器小例验收。
2. 以32个训练样本做S0/AB短跑，验证loss下降、梯度正常、无推理泄漏与模块开关有效；这一步不报正式AP。
3. V2X-R依次完成S0-C、S0-W；Astyx同时完成小样本adapter核查。v4 各线独立训练，不再存在教师准备依赖。
4. 在仅Normal/Fog验证集上完成A-W、B-W、AB-W以及SUP，先检查类型监督、支持率和残差是否真正工作。
5. 完成两数据集C/W四组及V2X-R关键强对照，冻结结构和超参数。
6. 根据吞吐实测补重复种子和机制消融，统一开启最终test三天气评估，生成结果与失败分析。

若代码修复、标签匹配或Astyx雪模拟没有通过检查，优先处理具体缺口，不能跳过后直接追求2–3点。

## 12. v4统计策略、恢复和比较契约

配置/checkpoint schema4与`teacher_free_v4`绑定。结构、损失、尺度、增强和优化器预算沿用v3；新增评测前固定权重BN统计重估。在线BN仍为eps=.001/momentum=.01；没有换归一化、增加训练micro或启用AMP。

每epoch评测前，从train完整8083帧按 `floor((i+.5)*8083/32), i=0..31` 固定取32帧，统计micro4、epoch0、无几何增强。C用Normal；W沿用原seed的Normal/Fog与来源扰动。只更新BN统计，不计算辅助/检测loss，不反向、不更新参数。reset后用PyTorch CMA，8个micro均值和各自无偏方差等权平均；不称全局合并方差。随后全部模块eval，同一统计用于该epoch所有验证天气及最终选中权重的所有测试天气，不在验证/test/Snow上校准。额外开销统一为每模型每epoch8次统计前向，30epoch共240次，与检测训练更新预算分列。

`latest.rank0.pt`角色为 `resume/online_running`，context退出后保存恢复所需在线状态；`selected.pt`在context内保存 `selected/train_refit_cma_v1`、训练样本/天气/策略/BN-buffer哈希清单。selected不能续训；导出拒绝在线latest、缺失或不符的重估清单。context恢复BN及其他buffers、原模式、momentum和Python/NumPy/CPU/CUDA RNG，独立loader不移动训练sampler。v2/v3 checkpoint均不能恢复成v4。

19份当前配置与78项pending矩阵已同步，科学比较契约完整绑定BN策略和loss。12项外部方法仍adapter_pending；只登记共同输入/预算/统计契约，原方法目标及教师成本待适配核实，不能声称已跑通。v2/v3完整最小源码及配置分别存入精简归档，不继续复制根配置。
